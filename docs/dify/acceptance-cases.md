# Dify 六案例验收清单

所有案例使用受控工作区和测试文件，不使用真实敏感文件。每个案例记录开始状态、Human Input 选择、返回错误码或结果、结束文件状态；不记录 API Key 或一次性令牌。

## 成功案例

### 成功案例 1：只读搜索

- 准备：工作区包含一个可访问的文本文件。
- 输入：自然语言要求搜索文件名关键词。
- Human Input：不进入确认。
- 预期：`search_files` 返回匹配元数据，文件无变化。

### 成功案例 2：确认后整理

- 准备：工作区包含 `incoming/notes.txt`，目标目录不存在冲突。
- 输入：要求将文件移动到 `organized/notes.txt`。
- Human Input：批准。
- 预期：`create_plan` 先返回确认文本；批准后执行成功，文件只移动一次并产生操作日志。

### 成功案例 3：确认后上传

- 准备：待上传文件不超过 15MB，目标目录在当前用户授权范围内且目标不存在。
- 输入：选择文件并指定相对目标目录。
- Human Input：批准上传。
- 预期：`upload_file` 返回相对路径和 `size_bytes`，文件写入限定工作区。

## 失败案例

### 失败案例 1：拒绝确认

- 准备：生成一个有效整理计划。
- 输入：保持计划内容不变。
- Human Input：拒绝或取消。
- 预期：不签发令牌、不调用执行接口、文件无变化。

### 失败案例 2：越权路径

- 准备：普通用户仅授权 `organized`。
- 输入：要求移动或上传到根目录或其他未授权目录。
- Human Input：不应出现确认环节；若已有计划，执行前再次复核。
- 预期：返回 `403 path_not_allowed`，文件无变化，令牌不被越权请求消耗。

### 失败案例 3：目标冲突或超限

- 准备：目标文件已存在，或上传文件超过 15MB。
- 输入：执行整理或上传。
- Human Input：不批准冲突操作。
- 预期：返回稳定错误码，拒绝覆盖或超限写入，文件状态保持不变。

## 证据要求

- 受保护接口使用 Provider 凭据调用；不要把 `X-API-Key` 的实际值写进文档。
- Docker 容器访问 Windows 服务使用 `host.docker.internal`，不能使用 `localhost`。
- 记录服务测试、插件测试和 Dify 镜像内置测试时必须分开。
