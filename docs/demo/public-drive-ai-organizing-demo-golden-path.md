# 公共盘 AI 整理 DEMO：黄金路径演示脚本

> 状态：演示脚本，依赖 [样例数据清单](public-drive-ai-organizing-demo-sample-manifest.md)。Windows/SMB 旁路写结论当前为 NOT_RUN，脚本不得使用“旁路不可写”“企业实机安全闭环”或“生产闭环”表述。

## 主话术

“员工用对话提出公共盘整理要求，AI 只生成结构化建议；系统按身份、权限、版本和指纹重新校验，展示影响预览，经确认后执行，所有动作可审计、可回滚，并把文件沉淀为可引用的知识资产。”

广告/多媒体项目是本脚本的第一套高真实感样例，不是产品唯一行业或唯一客户群体。

## 演示前检查

1. 使用演示专用工作区和 [样例数据清单](public-drive-ai-organizing-demo-sample-manifest.md) 的 10 个虚构文件；不得使用真实客户文件。
2. 记录每个 PDF/DOCX 的 `Asset`、`AssetVersion`、内容 SHA-256、解析/索引状态和 A/B 的显式 `PermissionGrant`。
3. 仅将 PDF/DOCX 送入 RAG 解析、切片和索引；JPG/AEP 只显示元数据，不宣称已解析。
4. 确认 A 对两个 `输出稿` 文件和两个目标目录都有长期移动权限，A 对敏感法务文件没有 QUERY 许可，B 对 A 内容与敏感法务文件均有显式 QUERY 许可。
5. 准备三类证据位置：Dify 运行详情、控制面/执行器审计与实际文件路径窗口。不要显示 API Key、会话令牌、一次性 approval token 或密码。

## 主线：A 低风险整理并验证真实路径

1. **A 登录。** 展示“公共盘 AI 整理 DEMO”，只展示 A 已授权的项目内容和当前身份。
2. **A 选择或上传文件。** 选取“星河食品有限公司 / 2026 春季新品上市整合传播项目”的混乱文件。展示 Asset/AssetVersion 创建和 `queued -> parsing -> indexed -> ready`，并明确 active 切换在 ready 后发生。
3. **真实 RAG 可查询性检查。** 以 A 查询一份有权 PDF/DOCX，展示真实返回的命中片段、`asset_version_id`、`chunk_id`、页码或段落、`current_path` 与 `version_path`。如果该查询入口、真实解析 runner 或索引写入尚未接线，停止在这里并标记“演示准备未完成”，不能以测试代码或空引用替代。
4. **A 提出整理要求。** 示例：“请按客户、项目阶段、文件类型整理输出稿，并把文件名规范为客户-项目-文件类型-版本。”
5. **展示候选而非写入。** Dify/LLM 仅输出 `operations_json`；展示两个 `move_rename` 候选，不能展示模型已移动文件。
6. **影响预览和服务端重验。** 展示 A 身份、ACL、AssetVersion、文件指纹、目标冲突、风险结论 `SELF_CONFIRM`、计划哈希和影响摘要。说明控制面计划摘要与执行器计划摘要不同，且二者均在服务器侧验证。
7. **A SELF_CONFIRM。** A 确认同一计划；B 不出现审批待办。一次性令牌只在内部适配调用栈签发/消费。
8. **展示实际路径变化。** 打开演示工作区文件管理器或 PowerShell 路径窗口，先后展示执行前/后：两个文件已从 `输出稿/` 移至 `验收交付/输出稿/`，内容 SHA-256 保持一致。若实际路径未变化或只看到 UI 成功消息，演示判定失败。
9. **展示审计和恢复依据。** 展示 `ExecutionJob=completed`、关联 `AuditEvent`、operation ID、执行前后相对路径及可回滚依据；不显示令牌或密钥。
10. **A 在移动后查询同一资产。** 查询主视觉 KV 或视频脚本内容。展示引用仍绑定原 `AssetVersion`、页码/段落和 `chunk_id`，同时 `current_path` 是移动后路径、`version_path` 是版本产生时的旧路径。

## 分支 1：A 越权检索失败

1. 保持 A 的可信 session，查询“内部法务评审意见中有哪些版权风险？”。
2. 展示安全结果：`DENY`、`retrieved_count=0`、`llm_invoked=false`、`citations=[]`。
3. 在安全审计/跟踪视图中核对：敏感资产路径、chunk ID、正文和版本 ID 没有出现在候选、评分、重排、LLM 上下文、引用或可泄漏日志中。
4. 说明 B 不能通过审批把该 DENY 改为 A 可读；approval 不是权限提升机制。

## 分支 2：B 的显式授权查询与上传

1. B 登录，上传一份新的脱敏 PDF/DOCX 到 B 已授权项目目录；展示独立 AssetVersion 和索引状态。
2. B 查询 A 的验收交付内容，展示命中引用；再查询 `版权授权证明/内部法务评审意见.docx`，展示命中引用。
3. 展示控制面 ACL 证据：B 的两类读取都来自明确 `PermissionGrant`；删除该授权后应回到检索前 DENY。不要使用“管理员天然可看全部内容”的话术。

## 演示失败处理

- 若 PDF/DOCX 未真实完成解析、切片、索引并出现查询内容，停止并标记 RAG 演示未就绪。
- 若目标冲突、身份/ACL 改变、指纹变化或计划哈希变化，展示服务端拒绝和零写入，而不是绕过或手工修复。
- 若 A 的敏感查询产生任何候选文本、引用或 LLM 调用，立即判定安全演示失败。
- Windows/SMB 旁路写尚未通过前，只说明“应用内受控执行路径已本地组合验收”，不得对实际公共盘直接写入做安全宣称。
