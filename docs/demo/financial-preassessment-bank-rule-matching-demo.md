# 资料预评估与银行规则匹配 DEMO

> 状态：V2 首板块的项目内受控样例设计。它不代表贷款审批、授信、额度测算、金融产品销售、真实公共盘接通或真实银行规则。

## 对外话术

用户上传或选择模拟资料后，系统将资料版本化、结构化，并根据演示银行规则样例做资料匹配度预评估，输出可匹配的示例银行类型、缺失材料和引用依据。结果仅供信息参考，不参与贷款申请、审批、授信、额度测算或金融产品销售。

## 受控样例与来源标签

样例位置为 `work/demo/financial-preassessment/source`，全部是虚构或脱敏的 PDF/DOCX：资料概览与授权说明、收入情况说明、资金流摘要、资产负债说明、经营情况说明、补充材料清单、内部资料核验说明和演示规则适用说明。

- 不使用真实身份证、真实账户、真实银行流水、真实征信或真实银行内部规则。
- `敏感资料/内部资料核验说明.docx` 仅用于权限负向控制；普通成员 A 无权检索。
- `rules/demo-bank-rules-v1.json` 的 `source_type=demo_fixture`，其中的示例银行名称和规则均为虚构演示条目。

## 确定性匹配输入与输出

确定性规则引擎必须消费控制面选择的 `RuleVersion` 和已授权 active `AssetVersion`，而不是 LLM、浏览器或 Dify 自报的规则/身份。

输入：已提供材料名称、已授权资料引用、规则版本。

输出：

- `match_score`：资料匹配度，只表示资料与演示规则的匹配程度。
- `result_level`：`MATCH`、`POSSIBLE`、`NOT_MATCH` 或 `MISSING_INFO`。
- 每条示例银行规则的已满足条件与缺失材料。
- 资料引用：`asset_id`、`asset_version_id`、`chunk_id`、页码或段落。
- 规则引用：`rule_set_id`、`rule_version_id`、规则条目 ID、规则版本指纹。
- 固定免责声明版本。

不得将 `match_score` 称作信用评分、授信评分、审批评分或额度评分。

## 演示问题与回答模板

问题：

> 这个客户资料匹配度是多少？能匹配哪些示例银行要求？还缺哪些材料？依据是什么？

回答模板：

```text
资料匹配度：<0-100，仅为演示规则匹配度>
规则版本：<demo RuleVersion>

可匹配：<示例银行规则及已满足材料>
可能匹配：<示例银行规则及待补材料>
暂不匹配：<示例银行规则及缺失材料>

资料依据：<AssetVersion / chunk / 页码或段落>
规则依据：<RuleVersion / rule_id>

免责声明：仅供资料完整度与规则匹配演示参考，不参与贷款申请、审批、授信、额度测算或金融产品销售。
```

LLM 只可在确定性结果之后润色上述解释，不能改变分数、结果等级、缺失材料、权限或规则版本。

## 权限负向控制

A 选择 `敏感资料/内部资料核验说明.docx` 查询时，必须在候选召回、评分、重排、LLM 上下文和引用前返回：

```text
DENIED
retrieved_count=0
llm_invoked=false
citations=[]
```

被拒绝的资料路径、正文、chunk 和规则推断不得泄露到结果或安全审计。
