## 2. 目标与成功定义

当前唯一目标是完成一个可向外部企业稳定演示、用于证明价值并争取下一阶段资源投入的最小 DEMO。

产品定位：

> 统一入口下的受控企业文档资产系统：同一份公共盘文件既能被授权整理，也能被授权查询；LLM 只提出建议，确定性服务负责身份、权限、确认/审批、版本、执行和证据。

最小 RAG 是本次 DEMO 的 **MUST**，必须与安全文件后台并行实施；完整企业 RAG 仍属于后续目标，不得借此扩展全格式、GraphRAG、知识图谱或生产级高可用。

本次不宣称生产就绪。对外只证明以下关键风险闭环：

1. **Same source**：文件整理和知识问答使用同一个 `Asset` 与 `AssetVersion`。
2. **Same permission**：文件读取、整理和检索共享同一套 ACL。
3. **Human authority**：LLM 只能建议；人和确定性服务才可确认、批准和执行。
4. **Verifiable control**：越权、过期确认/批准、内容变化和目标冲突都会失败关闭。
5. **Recoverable evidence**：全过程具备审计、引用、版本和恢复依据。

## 4. 不可更改的架构边界

| 组件 | 本次职责 | 权威性与禁止事项 |
| --- | --- | --- |
| 统一 Web/BFF | 唯一用户入口；登录会话、业务路由、权限裁决、影响预览、确认/审批、任务与审计展示 | 是业务控制平面；浏览器不得绕过它直达 Dify、执行器或 Qdrant |
| PostgreSQL | 保存 user/group 映射、资产与版本、ACL、计划、确认/审批、任务和审计 | 是业务与权限权威库 |
| Windows FastAPI 执行器 | 路径限制、批量预检、指纹和目标冲突重验、幂等执行、整批零写入、回滚、回收和恢复 | 是公共盘唯一写入边界；只接受 BFF 内部调用，不承担登录或最终业务授权 |
| Dify | 意图理解、严格结构化候选计划、回答生成和可替换模型编排 | 不是登录、ACL、正式确认/审批、事务、审计或公共盘写入边界 |
| 隔离解析/OCR worker | 对有限格式做解析、OCR、切片和版本处理 | 与文件写入执行器分进程；限制 CPU、内存、时间和网络权限 |
| Qdrant | 保存可重建、可删除、可切换的检索副本 | 不是权威库；公共盘原文件与 PostgreSQL `AssetVersion` 才是权威 |

补充约束：

- Keycloak 或现有企业 IdP 只证明身份并提供组/角色声明；逐资产 ACL 由 BFF/PostgreSQL 管理，首版不实现 Keycloak Resource/UMA。
- 现有一次性令牌可作为 BFF 到执行器的内部短时凭证，但不得返回浏览器或进入 Dify。
- BFF 的确认/批准记录必须绑定 actor、`plan_hash`、资产版本、`policy_version` 和 `expires_at`。
- DEMO 目录必须通过 Windows/SMB ACL 禁止普通用户直接写入，只允许执行服务账号写入；否则列为未闭环限制并停止对外演示。

## 5. 共同领域核心

统一入口只是交互层，`Document Asset` 才是文件整理与知识查询共用的领域核心。

- `User`、`Group`、`Role`：可信身份及组织声明。
- `Asset`：稳定 `asset_id`、当前路径、ACL 范围和生命周期。移动或重命名后 `asset_id` 不变。
- `AssetVersion`：`version_id`、内容哈希、大小、修改时间、来源以及 parser/index 状态。只有内容变化才创建新版本。
- `PermissionGrant`：主体、资源范围和允许动作。
- `Plan`：申请人、操作数组、文件指纹、`plan_hash`、`policy_version` 和过期时间。
- `Confirmation`：申请人针对某个具体计划的本次确认。
- `Approval`：预定义高风险操作的第二人授权；不能覆盖 `DENY`。
- `ExecutionJob`：幂等键、状态、lease/attempt 和失败原因。
- `AuditEvent`：actor、action、resource、`request_id`、before/after 和 result。
- `Chunk`：`asset_version_id`、`chunk_id`、页码/段落及 parser/embedding 版本。

RAG 引用必须绑定 `asset_version_id`，并展示资产当前路径；引用历史版本时必须明确历史路径。具体字段、状态枚举和内部 API 以执行总负责维护的唯一共同契约为准。

## 6. 权限、确认、审批与执行

术语不得混用：

- **permission**：主体长期被授权的资源和动作范围。
- **confirmation**：申请人确认本次 LLM 候选计划。
- **approval**：预定义高风险操作的第二人授权。
- **execution**：确定性服务在全部门禁满足后执行。

策略裁决至少包含四态：

| 裁决 | 含义 | 典型处理 |
| --- | --- | --- |
| `DIRECT` | 已授权且无需另行确认的低风险操作 | 读取/查询，以及授权目录内且不覆盖已有文件的低风险上传，由 BFF 校验后直接执行 |
| `SELF_CONFIRM` | 已授权但需要申请人确认本次具体计划 | A 确认后执行，B 不介入 |
| `APPROVAL_REQUIRED` | 策略预先允许申请升级的高风险操作 | A 确认并提交，B 依据角色和策略审批 |
| `DENY` | 权限或策略明确禁止 | 失败关闭，不得通过 B 审批绕过 |

黄金路径是员工 A 在本人授权目录内上传、查询，以及少量移动或重命名。LLM 只生成结构化建议，BFF/服务端重新校验身份、ACL、资产版本、指纹、目标冲突和风险并展示影响，A 对本次具体计划自行确认后执行，不强制管理员 B 审批。

管理员 B 只审批预定义高风险操作，例如回收、恢复、跨部门移动、敏感目录或大批量操作。

## 7. 唯一 DEMO 故事

### 7.1 黄金路径

1. 员工 A 从局域网统一入口登录。
2. A 上传固定“脏文件”样本；系统创建 `Asset + AssetVersion` 并显示解析/索引状态。
3. A 在同一对话提出整理要求；Dify 只返回严格结构化候选计划。
4. BFF 重新解析资产和权限，展示依据、源/目标、影响范围、冲突和策略裁决。
5. 常规整理得到 `SELF_CONFIRM`；A 确认本次具体计划后，BFF 内部调用执行器，B 不介入。
6. 执行器重验 ACL、`plan_hash`、资产版本/指纹、目标冲突、幂等键和内部短时凭证后移动或重命名。
7. A 在同一对话查询该文档，获得绑定 `asset_version_id`、页码/段落并显示当前路径的引用；移动后 `asset_id` 保持不变。
8. 展示按 `request_id` 串联的计划、确认、执行、索引、查询和审计证据。

### 7.2 必演负向控制

A 查询 B 专属或其他无权资产时，BFF 必须在检索前注入不可绕过的 ACL 过滤。无权资产不得进入召回结果、重排、LLM 上下文或可泄漏日志。

### 7.3 备用负向控制

在 A 确认或 B 批准后改变源文件指纹。执行器必须整批零写入、记录失败原因并要求重新规划。

## 10. 停止条件、许可与残余风险

### 对外演示停止条件

出现任一情况即不得进入对外演示：

- DSL/插件版本仍漂移。
- 普通用户能直接写 DEMO 公共盘。
- 任一 RAG 路径先召回无权文本再靠 LLM 删除。
- 确认/批准未绑定计划哈希和资产版本。
- 浏览器或 Dify 能直接调用文件执行器写入。
- 失败后无法明确证明文件和数据库的状态。
- 演示依赖不可控云端服务且没有固定降级方案。

### 许可要求

- Dify 存在附加限制许可证；外部商业演示前核对多租户和前端使用边界，默认采用 API-only、单内部 workspace。
- Docling/PaddleOCR 的代码许可不自动覆盖模型权重、字体和样本；演示前建立最小 SBOM 与模型/资产清单。
- 未完成许可核验的外部代码不得直接复制进入项目。

### 残余风险

- 当前原型身份可由客户端 `user_id` 影响，必须在 Gate 1/2 前由可信 session/token 替代。
- Windows/SMB ACL、服务账号和网络隔离若无法落地，DEMO 只能标为逻辑控制演示，不能宣称强制安全边界。
- 解析器处理不可信文档存在资源消耗与攻击面，必须隔离并限制资源、时间和网络。
- 新索引版本必须完全就绪后才切换 active；失败时继续服务旧版本。
- 模型与外部依赖需要预热和固定降级路径，避免演示稳定性依赖不可控网络。
