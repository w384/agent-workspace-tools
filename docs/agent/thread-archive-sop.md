# 线程归档重开 SOP（2026-08-14 版）

> 适用范围：多线程协作中的线程归档 / 重开 / 迁移。状态以 `docs/agent/thread-handoff-2026-08-14.md` 为准，本文件只存流程，不存状态。
> 角色权威定义见 `docs/agent/v2-role-map.md`。

## 0. 总流程（每线程 6 阶段）

| 阶段 | 动作 | 执行人 | 产出 |
| --- | --- | --- | --- |
| 0 | 更新交接包该线程章节 | 线程负责人 / Q | 交接包反映最新状态 |
| 1 | 归档前核验（发消息） | Q → 旧线程 | 旧线程回复【可归档】 |
| 2 | 归档旧线程 | Q（Codex 客户端） | 旧线程不可用 |
| 3 | 重建工作区 | Q（git worktree add/remove） | 标准路径就绪 |
| 4 | 开新线程 + 首条消息 | Q | 新线程复述六项 |
| 5 | 复述核对 | Q | 确认放行 |
| 6 | 更新交接包状态 | Q | 状态 = 已归档重开 |

## 1. 阶段 0 — 交接包更新

- 操作：编辑 `thread-handoff-2026-08-14.md` 对应线程章节（切片 / 验收 / 边界 / 路径 / 下一步），与磁盘真实产出对齐。
- 验证清单：
  - [ ] 章节引用的文件路径在磁盘上真实存在
  - [ ] 无未落盘的口头决策（如有，先落盘再归档）
  - [ ] 归档前不提交、不推送、不发布（保持脏改可查）

## 2. 阶段 1 — 归档前核验（发消息给旧线程）

- 通用核验消息模板：

```
【归档前核验 · <线程名>】你即将归档。只回复以下内容，不要自行移动目录或开启新改动：
① 你当前工作区完整路径
② 你维护的文件路径清单 + 状态（落盘 / 未落盘）
③ 在途任务卡点（如有）
④ 确认：交接包中你的章节内容完整，无遗漏的口头决策或未落盘结论
核验通过后由 Q 归档并在标准路径重开；新线程第一条消息 = 只读
frozen-v2-integration-contract.md + 共享交接包中你的章节。
```

- 验证清单（逐项核对旧线程回复）：
  - [ ] ① 工作区路径正确
  - [ ] ② 文件清单完整、状态明确
  - [ ] ③ 在途任务已收尾或明确移交
  - [ ] ④ 无未落盘决策
  - [ ] ⑤ 回复明确含【可归档】字样

## 3. 阶段 2 — 归档旧线程

- 操作：在 Codex 客户端对旧线程执行归档。
- 验证清单：
  - [ ] 旧线程从活跃列表移除
  - [ ] 归档后对比 `git status`，旧线程未产生新改动

## 4. 阶段 3 — 工作区重建（git worktree）

> 注：曾考虑 handoff_thread 迁移保对话。2026-08-18 运行时实测 `codex_app__handoff_thread` 存在且可调用（11 个 `codex_app__*` 线程工具全部可用，证据见 `.learnings/ERRORS.md` ERR-20260818-001）。本 SOP 仍以「归档 → git worktree 重建 → 新线程重开」为标准流程；如需改用 handoff_thread 迁移，须先经 Q 确认。

- 操作（在主 checkout `D:\AI\Codex\Projects\agent-workspace-tools` 执行）：
  1. 归档旧线程（阶段 2）后，删除跑偏 worktree：`git worktree remove D:\AI\Worktree\a904\...`
  2. 重建标准 worktree：`git worktree add D:\AI\Codex\Worktree\<branch-name> <branch>`
- 验证清单：
  - [ ] `git worktree list` 显示新路径已注册、旧路径已移除
  - [ ] 新路径下 `git status` / `git log` 正常
  - [ ] 旧路径（`D:\AI\Worktree\0328|12eb|a904`）已删除
  - [ ] 删除前已确认旧 worktree 无未提交工作（detached HEAD 且无脏改；如有先核验落盘）

## 5. 阶段 4 — 新线程首条消息

- 通用模板：

```
【<线程名> · 线程重开】你接替已归档的旧线程（旧对话不可用，禁止依赖旧记忆）。
开工前只读两份文件：
- docs/contracts/frozen-v2-integration-contract.md（权威契约）
- docs/agent/thread-handoff-2026-08-14.md（共享交接包，只读"<线程名>"一节）
确认你的工作区路径为 <目标路径>，与交接包记录一致。
第一步：读完两份文件后，用一段话复述六项——
① 权威契约 ② 当前切片 ③ 验收标准与基线证据
④ 边界 ⑤ 已知归属 / 在途项 ⑥ 工作区路径
等 Q 确认后再执行下一步。
发现文件缺失、路径不符或内容矛盾，立即报告，不要自行推断。
```

- 验证：新线程回复中报出的工作区路径与实际路径一致。

## 6. 阶段 5 — 复述核对

- 操作：对照交接包该章节逐项核对；对复述中超出交接包的细节，交叉验证是否在契约 / 角色地图原文中存在（防编造）。
- 验证清单：
  - [ ] ① 契约定位与边界口径正确
  - [ ] ② 切片描述一致
  - [ ] ③ 数字证据（测试数 / HEAD / 脏改数）与交接包一致
  - [ ] ④ 边界（DENY 前置、POSSIBLE/MISSING_INFO、match_score）正确
  - [ ] ⑤ 归属 / 在途项被提到
  - [ ] ⑥ 路径正确
  - [ ] 新增细节可溯源到契约原文
- 全对 → 回复："复述确认通过…"；任一项错 → 让它重读对应文件再复述，不放行。

## 7. 阶段 6 — 交接包更新

- 操作：路径表该行 + 章节标题 / 下一步改为"已归档重开，复述确认通过"。
- 验证：重新读文档确认无残留旧状态。
