# Dify 本机安全文件工具实施计划

## 目标

通过“Windows 本机安全文件服务 + Dify 插件 + Dify Workflow”，让 Dify 在限定工作区 `D:\AI\AgentWorkspace` 内扫描、分析和整理文件，并在任何写操作前由用户整批确认一次。

## 第一版范围

- 读取工具：列出文件、搜索文件、读取 15MB 以内文件内容。
- 文件接收：上传文件，不覆盖已有文件。
- 计划预览：创建文件夹、移动或重命名、移入 `.trash`。
- 安全确认：展示计划编号和整理明细，签发一次性确认令牌。
- 原子执行：整批预检，任一失败则整批不执行；执行中失败则自动回滚。
- 恢复能力：操作日志和回收文件保留 14 天，支持 `restore_operation`。
- Dify 集成：API Key、本机 FastAPI、Dify 插件工具和带 Human Input 的 Workflow。

## 固定约束

- 每批最多处理 10 个文件，创建文件夹不计入文件数。
- 单文件最大读取内容为 15MB；超过限制只返回元数据。
- `.trash` 和 `.file-manager` 不允许用户工具直接访问。
- 不覆盖已有文件或文件夹。
- 所有写操作必须使用一次性确认令牌。
- 操作日志保留 14 天。

## 实施阶段

1. **已完成**：安全路径、扫描、搜索、读取、上传和操作预览。
2. **已完成**：计划编号、确认摘要、计划保存和一次性令牌。
3. **已完成**：原子执行、自动回滚、回收和实际恢复。
4. **部分完成**：FastAPI 完整接口、API Key 和统一错误响应已完成；Windows 服务启动配置按当前范围不实施。
5. **未开始**：Dify 插件、Workflow 人工确认和端到端验证，按当前范围不实施。

## 当前批次完成状态

- `restore_operation` 已通过 API 实际恢复文件，并同步更新恢复计划、原计划和操作日志状态。
- 一次性令牌使用每计划 `RLock` 保护；API 并发测试验证 6 个请求中只有 1 个成功。
- FastAPI 已覆盖读取、上传、计划、令牌、执行、日志、恢复和过期清理接口。
- `/health` 公开；其余全部业务接口使用 `X-API-Key`，服务端未配置 Key 时返回 503。
- 当前完整自动化回归为 56 项测试。
